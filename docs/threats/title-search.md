# Threat analysis — Title search (step 2)

Status: approved 2026-10-12 (rate limiting: Postgres token bucket on the expensive path, in-memory limit plus caching on the catalog path). Every mitigation marked **AC** becomes an acceptance criterion of the step 2 implementation.

## Scope

Search field in the navbar. The visitor types part of a title; the server searches the Kinne catalog (all active titles, recommendable or not). Only when the catalog returns nothing, the server queries TMDB live (`/search/multi`), caches the answer for one day, and shows either "esse título não está em nenhum desses streamings" or a result that exists in the catalog. Selecting a catalog result opens `/titulo/<slug>`; a non-recommendable title page keeps "Vou assistir" and "Já vi", has no dice, no negative badge, and its events use source `search`.

## Assets

| Asset                                                | Why it matters                                                                 |
| ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| TMDB quota and API terms under the owner's token     | Abuse can get the token throttled or revoked, which also breaks the daily sync |
| Neon free tier (compute hours, storage, connections) | Search traffic keeps compute awake and can exhaust the monthly allowance       |
| Vercel free tier (function invocations, bandwidth)   | Same: site down for the rest of the month                                      |
| Visitors' search terms                               | Personal data under LGPD (can reveal tastes, health, religion)                 |
| Catalog suitability                                  | Search must not become a way to surface adult content                          |
| Test metrics                                         | `search` events must not be forgeable at scale or distort results              |

## Entry points and trust boundaries

1. Browser → search server action: **untrusted** free text, the first free-text input in Kinne.
2. Server → TMDB live API: third-party, **untrusted** responses, triggered by a visitor.
3. Server → database: catalog read and cache read/write.
4. Cache → other visitors: what one visitor's search stored is shown to others.

## Threats

Likelihood and impact are estimates (L/M/H).

### A. Input (Tampering, Injection)

| #   | Threat                                                                                                  | L / I | Mitigation                                                                                                                                                                 |
| --- | ------------------------------------------------------------------------------------------------------- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | SQL injection through the search term                                                                   | L / H | AC: Drizzle bound parameters only; no `sql.raw` with the term                                                                                                              |
| A2  | LIKE wildcard abuse (`%`, `_`, `\`) turning one search into a full scan or matching everything          | M / M | AC: escape `%`, `_` and `\` before any `ILIKE`; or use trigram similarity with a parameter, never a pattern built from input                                               |
| A3  | Huge or binary input (100 KB term, control characters, invalid UTF-8)                                   | M / M | AC: zod: string, NFC-normalised, control and format characters stripped, trimmed, 2–80 characters after normalisation; anything else rejected with the generic empty state |
| A4  | Reflected XSS: the UI echoes the term ("Nenhum resultado para …")                                       | L / H | AC: rendered as text only; no `dangerouslySetInnerHTML`; CSP                                                                                                               |
| A5  | Unicode tricks: look-alike characters, accents, case making the same search miss the cache or the index | M / L | AC: one normalisation function (NFC, lowercase, accents removed with `unaccent` or equivalent) used both for matching and for the cache key                                |
| A6  | Parameter injection into the TMDB request (`&include_adult=true`, path tricks)                          | L / H | AC: TMDB path fixed in code; the term passed only through `URLSearchParams`; `include_adult=false` set after the term so it cannot be overridden                           |
| A7  | Regex denial of service (a pattern that takes seconds on crafted input)                                 | L / M | AC: no regex built from the term; any fixed regex on the term is linear (no nested quantifiers)                                                                            |
| A8  | Search term or state placed in the URL (against §8 of security.md)                                      | M / L | AC: no query parameters; the term lives in component state and, if needed after back navigation, in `history.state`                                                        |

### B. Abuse and cost (Denial of service)

| #   | Threat                                                                                                         | L / I | Mitigation                                                                                                                                                                                                                       |
| --- | -------------------------------------------------------------------------------------------------------------- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| B1  | Cache-busting flood: a bot sends thousands of unique terms with no catalog match, each one costing a TMDB call | H / H | AC: per-client rate limit on the TMDB fallback (strict); a **global** TMDB budget per minute and per day shared by all visitors; when the budget is spent, the fallback is skipped and the UI shows the catalog-only empty state |
| B2  | TMDB throttles or bans the token, breaking the daily sync                                                      | M / H | AC: the live search uses a **separate** budget well below TMDB's limit so the sync always has headroom; on 429 from TMDB the live search stops for a cool-down window (circuit breaker)                                          |
| B3  | Catalog search flood keeping Neon compute awake and exhausting monthly hours                                   | M / H | AC: per-client rate limit on catalog search; results cached per normalised term (`use cache: remote`, short life); client debounce (≥ 300 ms) and minimum 2 characters; no search on every keystroke without debounce            |
| B4  | Expensive query on 22k rows (sequential scan per keystroke)                                                    | M / M | AC: index for the chosen match method (trigram GIN on the normalised title, or prefix index); `LIMIT 8`; statement timeout of 2 s on the search query                                                                            |
| B5  | Cache table growth without bound (one row per unique term)                                                     | M / M | AC: cache entries expire after 24 h and are purged by the daily sync; row cap with oldest-first eviction; size reported in `sync_runs`                                                                                           |
| B6  | Slow TMDB response holding the request open                                                                    | M / L | AC: 3 s timeout on the live call; on timeout, catalog-only empty state                                                                                                                                                           |
| B7  | Vercel invocations exhausted by automated traffic                                                              | L / H | AC: the rate limit rejects before any database or TMDB work; rejected requests do not reach the database where avoidable                                                                                                         |

### C. Data exposure (Information disclosure)

| #   | Threat                                                               | L / I | Mitigation                                                                                                                                                                                                                                                                                                                                                                                      |
| --- | -------------------------------------------------------------------- | ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | TMDB token reaching the client bundle or a response                  | L / H | AC: TMDB client is `server-only`; the browser never calls TMDB; responses carry only the fields the UI needs                                                                                                                                                                                                                                                                                    |
| C2  | Search terms stored or logged (LGPD: can reveal sensitive interests) | M / M | AC: terms are never logged and never stored with any client identifier; the cache key is a hash of the normalised term; usage events record only that a search happened and the selected title, never the text                                                                                                                                                                                  |
| C3  | Cache shows one visitor's search to another                          | L / L | Accepted by design: the cache holds public TMDB data, not who searched it; no identifier in the cache                                                                                                                                                                                                                                                                                           |
| C4  | Adult or explicit titles surfaced by the live TMDB search            | M / H | AC: `include_adult=false`; results with `adult: true` dropped; 18-rated and uncertified catalog titles appear in search (the user searched for them). Owner decision 2026-10-12 (PR #19): result posters are shown for every title, including 18-rated and uncertified ones, because the catalog images were checked and are not explicit. 18-rated titles stay out of daily picks and surprise |
| C5  | TMDB error details or stack traces reaching the visitor              | L / M | AC: any failure returns the same generic empty state; logs contain status code and endpoint path only (same rule as the sync)                                                                                                                                                                                                                                                                   |
| C6  | Catalog scraping through search                                      | M / L | Accepted: the catalog is public TMDB data; rate limits make bulk copying slow                                                                                                                                                                                                                                                                                                                   |
| C7  | Timing difference revealing whether a term hit the cache or TMDB     | L / L | Corrected in H2: it does reveal that someone searched the term recently                                                                                                                                                                                                                                                                                                                         |

### D. Integrity of results and events (Tampering, Spoofing)

| #   | Threat                                                                          | L / I | Mitigation                                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Malicious TMDB data from the live search (script in a title, forged image path) | L / H | AC: the same zod schemas as the sync (A1–A6 of catalog-sync) validate live results before caching or rendering                                                                                    |
| D2  | The live result links to an arbitrary page                                      | L / M | AC: a live TMDB result never becomes a link to an external site or a Kinne page; it only drives the "não está em nenhum desses streamings" message. Catalog results link only to `/titulo/<slug>` |
| D3  | Forged `search` events at scale distorting test metrics                         | M / M | AC: the event schema accepts `search` only with a valid catalog title; same rate limits and dedupe as other events; analysis can separate `search` from recommendation sources                    |
| D4  | Client claims a title is "recommendable" or sends its own slug list             | L / L | AC: the server derives recommendability and slugs; the client sends only the term and, on selection, the slug, validated with `isSlug` and looked up                                              |

### E. Privilege and configuration (Elevation of privilege)

| #   | Threat                                                         | L / I | Mitigation                                                                                                                                       |
| --- | -------------------------------------------------------------- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| E1  | The search path runs with write rights it does not need        | M / M | AC: search uses `kinne_app`; if the cache lives in Postgres, `kinne_app` gets `SELECT, INSERT, UPDATE` on the cache table only, nothing else new |
| E2  | Rate-limit state stores client IPs (against §7)                | M / M | AC: the limiter key is a salted hash of the IP with a salt that rotates daily; raw IPs are never written                                         |
| E3  | Rate limiter fails open (database down → unlimited TMDB calls) | M / H | AC: if the limiter cannot decide, the TMDB fallback is skipped (fail closed); catalog search may continue with the in-memory limit               |

### F. Repudiation and monitoring

| #   | Threat                                      | L / I | Mitigation                                                                                                                                                     |
| --- | ------------------------------------------- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | Abuse goes unnoticed until a quota runs out | M / M | AC: daily counters (catalog searches, TMDB fallbacks, rate-limit rejections, circuit-breaker trips), no terms, no identifiers; visible in the sync run summary |

### G. Second pass — gaps

| #   | Threat                                                                                                                                                                              | L / I | Mitigation                                                                                                                                                                                                                                    |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| G1  | **Rate-limit bypass by spoofed IP**: the limiter trusts the first `X-Forwarded-For` value, which the client controls; every request looks like a new visitor                        | H / H | AC: client IP taken only from the platform-provided value (`ipAddress()` from `@vercel/functions` or the header Vercel sets and overwrites), never from the raw `X-Forwarded-For` list; one helper used everywhere; test with a forged header |
| G2  | **IPv6 rotation**: one machine controls a whole /64 and gets a new "client" per request                                                                                             | M / H | AC: IPv6 addresses bucketed by their /64 prefix before hashing                                                                                                                                                                                |
| G3  | **Global budget as a weapon**: a distributed bot spends the shared TMDB budget so real visitors lose the fallback                                                                   | M / M | Accepted: degrades to catalog-only search, never breaks the site or the sync; F1 counters make it visible                                                                                                                                     |
| G4  | **Thundering herd**: many requests for the same uncached term at once each call TMDB                                                                                                | L / M | AC: single-flight per normalised term (in-process de-duplication plus an upsert "pending" marker); later requests wait or get the catalog-only state                                                                                          |
| G5  | **No negative caching**: a term with no TMDB match is fetched again on every repeat                                                                                                 | M / L | AC: "not found on TMDB" is cached for 24 h like a hit                                                                                                                                                                                         |
| G6  | **Cache cardinality**: `use cache: remote` keyed by free text lets a bot fill the shared cache with junk entries, evicting useful ones and adding cost                              | M / M | AC: cache only normalised terms of 3+ characters; the remote cache stores catalog results only, the TMDB fallback cache lives in the Postgres table with the row cap (B5)                                                                     |
| G7  | **Link prefetch amplification**: each result list renders up to 8 `<Link>`s, and Next prefetches each title page, multiplying database load per keystroke                           | M / M | AC: `prefetch={false}` on search results                                                                                                                                                                                                      |
| G8  | **Server action surface**: any exported server action is callable by ID, including ones the UI no longer uses; a lax body size limit accepts megabyte payloads                      | M / M | AC: search exposes exactly one action; `serverActions.bodySizeLimit` lowered to the smallest value that fits every action (e.g. 16 KB); `serverActions.allowedOrigins` left unset so Next's origin check stays strict                         |
| G9  | **Blocked or inactive titles resurfacing**: the TMDB fallback finds a title, the code maps it to the catalog by `tmdb_id`, and shows a title that is `is_blocked` or inactive       | M / H | AC: catalog search and fallback mapping both exclude `is_blocked`; inactive titles show the "não está em nenhum desses streamings" message; test both                                                                                         |
| G10 | **Search history kept on the device**: recent searches saved in `localStorage`, or the browser's own form history, exposing terms on a shared computer                              | M / L | AC: no search history stored by Kinne; input has `autocomplete="off"`                                                                                                                                                                         |
| G11 | **Client-side catalog**: a fuzzy-search library that downloads the catalog to the browser (fast to build, leaks the whole dataset and breaks the JS budget)                         | L / M | AC: matching happens only on the server; no new client dependency for search                                                                                                                                                                  |
| G12 | **Third-party scripts reading the field**: analytics or monitoring that records inputs or session replays                                                                           | L / M | AC: no session replay or input capture; any analytics records page paths only                                                                                                                                                                 |
| G13 | **Total request time**: catalog query + limiter + TMDB call chained without an overall cap                                                                                          | L / L | AC: overall action deadline of 5 s; whatever is not done returns the generic state                                                                                                                                                            |
| G14 | **`unaccent` and index mismatch**: the normalisation in SQL differs from the one in TypeScript, so cache keys and matches disagree, or the index is not used and every search scans | M / M | AC: one normalisation definition: an immutable SQL wrapper around `unaccent(lower())` used in the index and the query, mirrored by a TypeScript function with shared test cases                                                               |
| G15 | **Limiter table writes and contention**: one hot row for the global budget, many rows for buckets, growing forever                                                                  | M / L | AC: atomic `UPDATE … RETURNING` per bucket; expired buckets purged daily; global budget as a single counter row reset per window                                                                                                              |
| G16 | **Salt handling**: the IP-hash salt stored in the database next to the hashes, or never rotated, makes hashes reversible by brute force over the IPv4 space                         | M / M | AC: salt derived from a secret in the environment plus the current date (HMAC), never stored; old buckets become unlinkable after rotation                                                                                                    |

### H. Third pass — gaps

| #   | Threat                                                                                                                                                                                   | L / I | Mitigation                                                                                                                                                                                                                           |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| H1  | **Shared network blocked (CGNAT, university Wi-Fi)**: test participants in the same room share one public IP, hit the per-client limit together and see search fail during the user test | H / H | AC: per-IP limits sized for a classroom (at least 30 people searching at once); the strict protection comes from the global TMDB budget, not from a tight per-IP limit; limits configurable without a deploy (environment variables) |
| H2  | **Cache as a side channel**: a fast answer for a rare term reveals that someone searched it in the last 24 h (correction of C7)                                                          | L / L | Accepted: no identity or time is revealed; the fallback cache answer time is padded to the same minimum as a TMDB call only if this becomes a concern                                                                                |
| H3  | **Search term in a URL through implementation choice**: a GET route like `/busca/<termo>` or `/api/search?q=` puts terms in Vercel request logs, browser history and the Referer header  | M / M | AC: the term travels only in a POST body (server action); no route contains the term; covered by a test that lists routes                                                                                                            |
| H4  | **Normalisation cost before the length check**: NFC and unaccent run on a megabyte string before zod rejects it                                                                          | L / L | AC: reject raw length above 200 code units first, then normalise, then apply the 2–80 rule                                                                                                                                           |
| H5  | **Misleading empty state**: a rate-limited or budget-exhausted visitor sees "nenhum resultado" and concludes the title is not on any streaming                                           | M / M | AC: rate limit, budget exhausted, timeout and error share one neutral message ("Não conseguimos buscar agora. Tente de novo em instantes."), distinct from the real "not found" and from "não está nesses streamings"                |
| H6  | **Crawl amplification**: the catalog grew from ~2.9k to ~22k pages; crawlers and scrapers walking every `/titulo/<slug>` keep Neon awake                                                 | M / M | AC: title pages cached; sitemap lists recommendable titles only; non-recommendable pages carry `noindex`; page requests share the per-client limiter on cache misses                                                                 |
| H7  | **Visitor IP sent to TMDB by result images**: posters in the result list load from `image.tmdb.org`, a third party                                                                       | H / L | Accepted, already true for every page; stated in the privacy text (LGPD)                                                                                                                                                             |
| H8  | **Vendor lock in the IP helper**: `@vercel/functions` used directly across the code (RNF11)                                                                                              | M / L | AC: one `getClientIp()` helper is the only place that knows the hosting provider                                                                                                                                                     |
| H9  | **JS budget broken by a navbar component on every page** (home ≤ 150 KB gzip)                                                                                                            | M / M | AC: the search panel loads on demand (dynamic import on focus/click); Lighthouse CI budget must pass                                                                                                                                 |

### I. Final pass — gaps outside the code

| #   | Threat                                                                                                                                                                                                                         | L / I | Mitigation                                                                                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| I1  | **Preview deployments write to production**: Vercel Preview still uses production database credentials; step 2 adds the first writes from the site (cache table, limiter buckets), so testing a preview writes into production | H / H | Prerequisite, owner: Preview environment variables point to the Neon develop branch before step 2 is tested on a preview                                                                              |

| I3  | **Inaccessible search**: a custom dropdown that keyboard and screen-reader users cannot operate (a serious accessibility issue is a stop criterion)                                                                            | M / M | AC: WAI-ARIA combobox pattern (`role="combobox"`, `aria-expanded`, `aria-activedescendant`, listbox options); full keyboard use (arrows, Enter, Esc); results count announced in a polite live region |

Functional gap found while reviewing (not a threat): catalog search must match the original title and the pt-BR title, and a TMDB fallback hit whose `tmdb_id` is in the catalog must show the catalog title rather than the "not on these streamings" message.

## Decision needed: rate limiting (RNF11 portability)

| Option                | Pros                                                       | Cons                                             |
| --------------------- | ---------------------------------------------------------- | ------------------------------------------------ |
| Postgres token bucket | Portable, no new vendor, works across serverless instances | One write per limited request; keeps Neon awake  |
| Vercel firewall rules | No code, rejects before the function runs                  | Vendor-only (RNF11); free-plan limits unverified |
| Upstash Redis         | Fast, built for this                                       | New vendor and secret; against RNF11             |

**Recommendation:** Postgres token bucket on the expensive path only (TMDB fallback and the global TMDB budget), where cross-instance accuracy matters; in-memory per-instance limit plus caching and debounce on the cheap catalog path. This replaces the temporary in-memory limit on `/api/revalidate` too.

## Accepted risks

- C3, C6, C7 as above.
- In-memory limits on the catalog path are per instance, so a distributed bot gets more than the nominal rate; caching and the statement timeout bound the cost.
